# Training

## Principle

Nothing makes "concepts" appear by itself. With reconstruction loss alone, the memory learns whatever dense code is cheapest. We shape it with **capacity limits plus several objectives**, and add them **in stages**, each with its own eval, so we can tell which part broke.

## Objectives

| Objective | Purpose |
|---|---|
| **Reconstruction** (memory → original chunk) | Memory must hold the content |
| **Compression** (memory → concise target, from verbose→concise pairs) | Teaches density control; stops verbosity being copied |
| **QA** (memory + question → answer) | Memory must hold *usable* meaning, not just surface text |
| **Paraphrase consistency** (memory(x) ≈ memory(paraphrase(x))) | Pushes toward meaning over wording |
| **Per-slot QA** (`<slot:i>` + question → answer about idea i) | Ideas become localised and addressable |
| **Multi-slot reasoning** | Reasoner must combine ideas |
| **Capacity penalty** (few slots, optional KL/info bottleneck) | Forces abstraction |

## Curriculum

1. **Autoencode (T0).** chunk → K vectors → reconstruct. Frozen base, train the encoder LoRA and memory queries only. The decoder LoRA can be off at first (just a frozen decoder).
2. **Compress and density control.** Add verbose→concise pairs and density tokens; train the decoder LoRA.
3. **QA.** Add question answering from memory, using synthetic QA generated by a larger LLM.
4. **Idea slots (T1).** Slot attention over T0, plus per-slot QA and slot-ablation training.
5. **Latent reasoning.** Reasoner LoRA plus multi-slot tasks.
6. **Persistence (T2).** Promotion and retrieval across documents and sessions.

## Data

- **Reconstruction:** any clean text (e.g. Wikipedia, FineWeb-Edu samples).
- **Verbose→concise:** summarisation sets (CNN/DM, XSum, arXiv abstracts), plus synthetic "make this verbose" / "make this terse" pairs generated by a larger LLM.
- **QA:** synthetic question/answer pairs per chunk, generated by a larger LLM.

## Core evals (run every stage)

- **Reconstruction:** token accuracy, BLEU/ROUGE vs. original.
- **Memory necessity:** score with real memory vs. zeroed or shuffled memory. The gap must be large.
- **QA from memory vs. QA from full text:** ratio close to 1.
- **Density:** output length for each density token, and QA coverage per output token.
- **Compression ratio:** input tokens ÷ memory vectors.
- (Stage 4+) **Slot locality:** ablate slot i → drop on i-questions vs. others.

## Stage 3: QA from memory

Config: `configs/stage3.yaml`. Starts from the Stage 2 checkpoint, K = 16. Mix: 50% `<answer>` (SQuAD, paragraphs ≤ 4 chunks), 25% `<full>` replay (half 1-chunk WikiText, half whole XSum article), 25% `<terse>` XSum replay. Decoder LoRA at 3e-4, encoder side × 0.33, as in Stage 2.

Every validation logs `answer_val_loss`, QA EM/F1 under real/shuffled/zeroed memory (`qa_*`), the `<full>` gap (zeroed − real `<full>` val loss) and density metrics on `val_gen_samples` examples. At the end the trainer writes `<run>/eval/stage3.{json,md}`: regression flags against the Stage 2 band (`engram.eval.report.STAGE2_GATES`) and memory F1 ÷ text-QA control F1, with a K=32 recommendation below 0.5. Training-time QA uses only a few examples. Use `eval.py --qa` (200 examples) for the headline ratio.

How to run:

```
# 1. text-QA control (cached to runs/text_qa_control.json)
uv run scripts/train_text_qa.py --config configs/text_qa.yaml
# 2. Stage 3 (overnight)
uv run scripts/train.py --config configs/stage3.yaml --init-from runs/20261125-163535/ckpt-600.pt
# 3. final evals
uv run scripts/eval.py --run runs/<stage3> --qa
uv run scripts/eval.py --run runs/<stage3> --suite density
```

### Results (2026-11-26): negative

Run `runs/20261126-072712` (640 steps, ~2.3 h). Control `runs/text-qa-20261126-064050` (320 steps, 46 min).

| 200 SQuAD dev | EM | F1 |
|---|---|---|
| memory, real | 0.005 | 0.051 |
| memory, shuffled | 0.000 | 0.048 |
| memory, zeroed | 0.000 | 0.032 |
| base zero-shot (paragraph in prompt) | 0.070 | 0.196 |
| text-QA control | 0.635 | 0.687 |

Memory ÷ control F1 = 0.074. Real barely beats shuffled, so memory is not used for answers. The Stage 2 gates (XSum) all passed: `<full>` gap 2.00, terse/article 0.128, full/article 0.884, ROUGE-L 0.203.

Diagnosis (40 dev paragraphs, `<full>` reconstruction from memory):
- Stage 2 checkpoint: the gold answer appears in the reconstruction 7.5% of the time; token F1 vs paragraph 0.26. K = 16 memory holds gist, not the specifics SQuAD asks about.
- Stage 3 checkpoint: `<full>` on SQuAD paragraphs outputs a short answer-like string ("1999") and stops. `<answer>` overrode `<full>` on the input type it was trained on; the XSum-only gates could not see it.

Next: re-plan with K = 32, all three modes trained jointly (with `<full>` replay on SQuAD paragraphs), and gates for `<full>` on SQuAD and answer-in-reconstruction.

## Stage 3b: K = 32, joint modes (unattended pipeline)

`scripts/stage3b.py` runs, unattended and in order: K=32 warm-up (`configs/stage3b_warmup.yaml`) → recall gate (answer recall of `<full>` on 40 SQuAD dev paragraphs, threshold 0.25; `engram.eval.report.recall_gate`) → gate summary → joint stage (`configs/stage3b_joint.yaml`, initialised from the warm-up's last checkpoint) → text-QA control (`configs/text_qa_3b.yaml`) → final `qa`, `recall` and `density` evals of the joint run → final summary (memory QA EM/F1 real/shuffled/zeroed, control F1, memory ÷ control ratio, answer recall, all Stage 2 and SQuAD `<full>` regression gates).

Everything goes under `runs/stage3b/`: derived configs, `warmup/<ts>`, `joint/<ts>`, `text-qa-<ts>`, `gate.{json,md}`, `final.{json,md}` and `state.json`. Gate below 0.25 → the pipeline writes the gate summary, prints the reason and stops (exit 1) before the joint stage. Re-running the same command resumes: finished stages are skipped (state.json) and an interrupted training stage resumes from its latest checkpoint. Budget ~7.2 h on CPU.

How to run:

```
HF_HOME=$PWD/.hf HF_HUB_OFFLINE=1 nohup uv run scripts/stage3b.py > runs/stage3b.log 2>&1 &
# smoke (tiny steps, runs_smoke_k32/stage3b; --gate-threshold 0 so the untrained gate passes)
HF_HOME=$PWD/.hf HF_HUB_OFFLINE=1 uv run scripts/stage3b.py --smoke --gate-threshold 0
```

## Fact objective: fact weighting + cloze task (unattended pipeline)

Stage 1 settings (WikiText only, 2000 train chunks, lr 0.002, batch 4, frozen decoder, memory adapter rank 8) with two objective changes: fact-weighted `<full>` loss (`fact_weighting: true`, weights from the frozen decoder under zeroed memory) and the cloze task (`cloze_ratio: 0.3`).

`scripts/fact_objective.py` runs: K=16 train (`configs/fact_k16.yaml`, 3000 steps) → eval (answer recall on 40 SQuAD dev paragraphs; ROUGE-L real/shuffled/zeroed on 15 WikiText val chunks and 15 SQuAD dev paragraph chunks) → pass? stop : K=32 train (`configs/fact_k32.yaml`, 4000 steps) → same eval → summary. Pass = answer recall ≥ 0.15 and WikiText real ROUGE-L > shuffled (`engram.eval.report.fact_arm`). The summary compares each arm with K=16 Stage 1 and K=32 WikiText-only baselines.

Everything goes under `runs/fact_objective/`: derived configs, `k16/<ts>`, `k32/<ts>` (eval in `<run>/eval/fact_eval.json`), `summary.{json,md}` and `state.json`. Re-running the same command resumes from finished stages / the latest checkpoint.

How to run:

```
HF_HOME=$PWD/.hf HF_HUB_OFFLINE=1 nohup .venv/bin/python scripts/fact_objective.py > runs/fact_objective.log 2>&1 &
# smoke (tiny steps, runs_smoke_fact/; --force-fail so both arms run)
HF_HOME=$PWD/.hf HF_HUB_OFFLINE=1 .venv/bin/python scripts/fact_objective.py --smoke --force-fail
```
